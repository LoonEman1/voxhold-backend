# Разработка Voxhold

Единые правила обоих репозиториев: [ветки, CI и версии](docs/release-workflow.md).
Рабочая ветка создаётся от `dev`; изменения попадают в `dev` через PR и зелёный
CI. Для обычных PR используется squash. Прямые записи в `dev`/`main`, обход
проверок, force push и удаление защищённых веток не допускаются.

Для выпуска подготовьте одинаковый `VERSION` обоих компонентов, метаданные
пакета фронтенда и `RELEASE_NOTES.md`. Релизные PR `dev` → `main` сливаются через
merge commit. После успешного CI образы, неизменяемые теги и релизы публикуются
автоматически. До общей версии 2.0.0 сохраняются исторические номера.

X.Y.Z: X меняется при крупных или несовместимых изменениях, Y — при новых
совместимых функциях, Z — при исправлениях текущей минорной версии. При увеличении
X сбрасываются Y/Z, при увеличении Y сбрасывается Z.

Проверяйте тесты, типы/линтеры, сборку и браузерные сценарии. На бэкенде также
обязательны race detector и runtime-проверка утечек горутин Go 1.27. Не публикуйте
секреты, базы, приватные логи и данные пользователей. Сначала обновляется бэкенд
с миграциями, затем фронтенд; старые бэкапы удаляются после успешных проверок.
