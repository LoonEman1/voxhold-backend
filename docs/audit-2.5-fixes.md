# Исправления аудита 2.5 и повторное ревью

Проверено 30 октября 2026 года. Изменения находятся в ветке
`codex/audit-2-5-fixes` в backend, frontend и deploy. Публичный инстанс
не обновлялся; локальные контейнеры использовались только для проверок.

## Пять воспроизведённых ошибок backend

| Ошибка | Исправление | Регрессия |
|---|---|---|
| Один NUL в отложенном сообщении останавливал очередь | Валидация содержимого, изоляция ошибочных заданий, до пяти попыток с задержкой; напоминания обрабатываются независимо | `internal/community/scheduled_safety_test.go` |
| Забаненный автор мог отправить запланированное личное сообщение | Проверка активного автора при отправке внутри транзакции, отмена pending-заданий при бане | `internal/community/review_test.go`, `internal/server/sqlite/repository_test.go` |
| Обычный или отложенный опрос канала превращался в текст | Все сообщения с Poll проходят полный путь сохранения, включая идемпотентные повторы | `internal/community/channel_poll_test.go` |
| Очистка могла удалить файл уже отправленного вложения | Сначала атомарно помечается незанятый файл в БД; отправка и постановка в расписание проверяют ту же запись в write-транзакции | `internal/attachments/cleanup_concurrency_test.go`, 12 конкурентных запусков с WAL и пулом соединений |
| После 200 бесед/заданий старые записи становились недоступны | Курсоры, ограниченный размер страницы, отдельное получение беседы, фильтр статуса заданий; участники загружаются одним пакетным запросом | `internal/community/pagination_test.go`, более 200 записей |

Основные коммиты: `1fcd9b1`, `e518824`, `f5bf051`, `2c0b576`, `554eeb9`.

## Согласованные изменения API

- `GET /api/v1/me/conversations?limit=100&before=<cursor>` возвращает
  `{conversations, has_more, next_cursor}`.
- `GET /api/v1/conversations/{id}` проверяет членство и возвращает одну беседу.
- `GET /api/v1/me/scheduled-messages?limit=100&before=<cursor>&status=pending`
  возвращает `{scheduled_messages, has_more, next_cursor}`. Допустимы также
  `sent`, `failed`, `cancelled` или отсутствие фильтра.
- `limit` — от 1 до 200. Без параметров пагинации сохранён старый контракт
  массива максимум из 200 записей. Обновлённый frontend проходит все страницы.
- `GET /api/v1/attachments/{id}/thumbnail` возвращает JPEG до 480×480 с теми же
  правами, что оригинал. Одновременно генерируются максимум два превью,
  в памяти хранится максимум 64; оригиналы остаются единственной постоянной
  копией. Удалённые вложения возвращают 410 даже при наличии превью в кэше.
- `HEAD /api/v1/attachments/{id}/content` позволяет проверить доступность без
  скачивания тела. `attachments.changed` содержит scope и `attachment_ids`.
- Активные документы и неизвестные image MIME отдаются как скачиваемые файлы;
  сохранены `nosniff` и `Content-Security-Policy: default-src 'none'; sandbox`.

## Обновление

Нужна миграция **000032_schedule_retries**: `attempts`, `next_attempt_at` и индекс
очереди. Штатный updater/migrate должен выполнить её **до запуска нового backend**.
Порядок: резервная копия БД → миграции → backend → frontend → обновление edge.
Новые колонки используются worker и API списка заданий; запускать новый backend
на схеме 31 нельзя. Откат схемы допустим после остановки нового worker.

Standalone Compose теперь публикует HTTP на `127.0.0.1` по умолчанию. Внутри
контейнера `HTTP_LISTEN_ADDRESS=0.0.0.0` сохранён. Публичный доступ обеспечивает
TLS-прокси из deploy-репозитория.

`golang.org/x/net` обновлён с 0.60.0 до 0.62.0; версия исправляет
[GO-2026-6866](https://pkg.go.dev/vuln/GO-2026-6866). До обновления затронутый
HTML-пакет не вызывался проектом. CI дополнен govulncheck v1.9.0 для production
пакетов Linux. Финальный скан: 0 достижимых уязвимостей и 0 затронутых
импортируемых пакетов; остаётся запись о неиспользуемом OpenPGP в required-модуле.

## Проверки

- `go test ./...` и `go vet ./...` — успешно на Go 1.27.3.
- `go test -race -p 4 ./internal/... ./cmd/...` — успешно в Linux-контейнере
  `golang:1.27.3`, включая обновлённый x/net и проверки вложений.
- `govulncheck ./cmd/... ./internal/...` для Linux/amd64 — успешно.
- Docker Compose config подтвердил loopback для HTTP.
- В deploy прошли оба теста `test_edge_config.py`: доступ через публичный edge
  и HSTS `max-age=31536000; includeSubDomains` в обоих вариантах Caddy.
- На frontend прошли 340 unit/компонентных тестов, 48 UI и 16 performance,
  reliability и media E2E; lint, typecheck, production build и Docker test.
  Подробная матрица 18 пунктов хранится в frontend в
  `docs/audit-2.5-fixes-status.md`.

Повторное ревью проверило границы транзакций очистки/отправки, запрет отправки
после бана, сохранение опросов и повторов, сортировку/ACL курсоров, MIME и
доступ к превью. В проверенных сценариях открытых регрессий не осталось.
