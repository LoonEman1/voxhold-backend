# Дизайн QOL-04 (отображаемое имя) и QOL-08 (категории каналов)

Статус: черновик. Эти задачи не реализованы: каждая меняет десятки запросов и типов, и
безопасно сделать их можно только с запуском полного набора тестов и ручной проверкой UI.

## QOL-04. Отображаемое имя

- Колонка `user_profiles.display_name TEXT NOT NULL DEFAULT ''` (0–32 символа; правила символов
  из `account.NormalizeUsername`, SEC-08, без требования уникальности). Редактируется через
  существующий `PATCH` профиля.
- Где отдавать: автор сообщений (`message.Author`), участники сервера, presence, поиск, уведомления,
  карточка профиля. Для каждого места найти SQL, где выбирается `users.username`, и добавить
  `COALESCE(NULLIF(user_profiles.display_name,''), users.username)` в отдельное поле
  `display_name` (поле `username` не меняется — на него завязаны упоминания и логин).
- Frontend показывает `display_name || username`, в карточке — оба; упоминания остаются по
  `<@id>` и логину.
- Риски: много JOIN на горячих путях (история канала) — добавить LEFT JOIN по первичному ключу;
  тесты на старые клиенты (новое поле необязательное).

## QOL-08. Категории каналов и порядок

- Вид канала `category` (миграция расширяет CHECK у `channels.kind`, пересоздание таблицы с
  сохранением данных — рискованно, поэтому лучше отдельная таблица `channel_categories(id,
  server_id, name, position)` и колонка `channels.category_id`).
- `PUT /api/v1/servers/{id}/channels/order` принимает массив `{id, position, category_id}` и
  применяет одной транзакцией (owner/admin), затем realtime-событие `channel.updated`.
- Frontend: сворачиваемые категории (состояние в localStorage), перетаскивание мышью и
  клавиатурой (стрелки + Alt) без новых библиотек.
- Риски: доступность по клавиатуре, порядок голосовых и текстовых каналов в одном списке,
  совместимость со старым клиентом (он игнорирует `category_id`).
