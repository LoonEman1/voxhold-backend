# Voxhold backend

Self-hosted backend for Voxhold: HTTP API, realtime events, voice rooms and
screen streaming. The server is written in Go, stores application data in
SQLite and is distributed as a multi-platform container image.

## Features

- invite-only registration and token-based sessions;
- server membership, roles, bans and account deletion;
- text and voice channels;
- messages, editing, deletion, search, context, pins and read state;
- authenticated realtime events over WebSocket;
- server-relayed WebRTC voice rooms;
- server-relayed or peer-to-peer screen streaming;
- configurable abuse protection, login blocking and connection limits;
- SQLite migrations and idempotent first-instance bootstrap;
- graceful shutdown, health checks and non-root container runtime.

## Technology

- Go 1.26;
- standard-library `net/http` routing;
- SQLite through `modernc.org/sqlite` (no runtime CGO dependency);
- `coder/websocket` for realtime transport;
- Pion WebRTC for voice and streaming media.

The container includes three commands:

- `voxhold` — API, WebSocket and WebRTC server;
- `voxhold-bootstrap` — creates the initial instance and owner;
- `migrate` — applies SQLite schema migrations.

## Quick local start

Requirements: Docker Engine and Docker Compose v2.

```bash
cp .env.example .env
docker compose up --build
```

On the first start, migrations run before bootstrap and the API. If
`BOOTSTRAP_PASSWORD` is empty, read and save the generated owner password:

```bash
docker compose logs bootstrap
```

The local API is available at `http://localhost:8080`; its health endpoint is
`GET /healthz` and returns `204 No Content`. Default media ports are
`50000/udp` for voice and `50001/udp` for screen streaming.

Stop the local stack without deleting its SQLite volume:

```bash
docker compose down
```

The repository Compose file is intended for local/backend-only operation. For
a public server with HTTPS, Caddy, backups, automatic updates and an optional
replaceable website, use
[`LoonEman1/voxhold-deploy`](https://github.com/LoonEman1/voxhold-deploy).

## Published image and releases

Pull requests and pushes to `main` test the backend and build its container
without publishing it. A Git tag matching `v<major>.<minor>.<patch>` publishes
the tested multi-platform `linux/amd64` and `linux/arm64` release.

For example, release `v0.1.0` publishes three tags pointing to the same image:

```bash
docker pull ghcr.io/looneman1/voxhold-backend:0.1.0
docker pull ghcr.io/looneman1/voxhold-backend:0.1
docker pull ghcr.io/looneman1/voxhold-backend:latest
```

Create a release after the desired commit is merged into `main`:

```bash
git tag v0.1.0
git push origin v0.1.0
```

Use the exact `0.1.0` tag for normal production deployments. The `0.1` and
`latest` tags move to newer compatible and stable releases respectively; an
OCI digest is the immutable reference. Each release contains SBOM and
provenance attestations generated by GitHub Actions.

## API overview

The public API prefix is `/api/v1`.

- `/api/v1/instance` — instance metadata and protocol version;
- `/api/v1/auth/*` — registration, login, refresh and logout;
- `/api/v1/me/*` — current profile, servers and incoming invitations;
- `/api/v1/servers/*` — members, roles, bans, channels and invitations;
- `/api/v1/servers/*/channels/*/messages` — message history and mutations;
- `/api/v1/servers/*/messages/search` — full-text message search;
- `/api/v1/ws` — authenticated realtime, voice and streaming signaling.

Protected HTTP endpoints use `Authorization: Bearer <token>`. Registration is
invite-only. WebSocket clients authenticate after connecting and receive the
current membership, read, presence, voice and stream state.

The repository does not currently publish an OpenAPI document. The route
handlers under `internal/*/http` are the source of truth for request and
response fields.

## Configuration

Copy [`.env.example`](.env.example) and review every value before deployment.
Important groups are:

- `DATABASE_*`, `MIGRATIONS_PATH`, `RESET_DATABASE` — SQLite lifecycle;
- `INSTANCE_NAME`, `BOOTSTRAP_*` — one-time instance initialization;
- `HTTP_*`, `TRUST_PROXY_HEADERS` — HTTP listener and trusted proxy behavior;
- `AUTH_*`, `INVITE_*`, `LOGIN_*`, `WS_*` — abuse protection;
- `WEBRTC_*` — public media address, UDP ports, limits and optional STUN/TURN.

On a public server, `WEBRTC_PUBLIC_IP` must be the server's reachable public
address and the configured UDP ports must be allowed by both host and provider
firewalls. Enable `TRUST_PROXY_HEADERS` only when the API is reachable solely
through a trusted reverse proxy that overwrites forwarding headers.

## Development

```bash
go mod download
go test ./...
go vet ./...
```

Build the binaries locally:

```bash
go build ./cmd/api
go build ./cmd/bootstrap
```

Pull requests, pushes to `main` and release tags run tests and `go vet`. The
container job runs only after those checks succeed. Pull requests and `main`
build without publishing; only SemVer release tags publish to GHCR.

## Security

Do not expose SQLite files, `.env`, Docker socket or the backend HTTP port
directly to the Internet. Terminate TLS at a trusted reverse proxy and expose
only TCP 80/443 plus the configured WebRTC UDP ports.

Please do not report vulnerabilities in a public issue. Follow
[SECURITY.md](SECURITY.md) instead.
