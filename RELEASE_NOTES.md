# Voxhold Backend 2.5.0

Минорный релиз от 30 октября 2026 года. Новых миграций нет; схема остаётся 000031.

- Адресаты уведомлений отбираются в SQL до загрузки пользователей; сохранены
  упоминания, ответы, подписки обсуждений, настройки уведомлений и проверки доступа.
- Одинаковые WebSocket-события кодируются один раз на рассылку. Персональные
  реакции и отфильтрованные snapshots получают собственное представление.
- Отдельные AMD64-образы `2.5.0-amd64-v1` и `2.5.0-amd64-v3` содержат по одному
  варианту API. Обычный `2.5.0` остаётся переносимым: amd64-v1 и arm64.
- Release-сборки используют trimpath и удаляют отладочные секции. API остаётся
  на encoding/json; перехода публичного кода на encoding/json/v2 нет.
- Установщик и обновлятор в voxhold-deploy автоматически выбирают v1/v3,
  проверяют запуск CPU до остановки сервиса и поддерживают принудительный v1.

Notification candidates are filtered in SQL before materialization; identical
WebSocket broadcasts share one JSON encoding while preserving per-user data and
access filtering. AMD64 v1/v3 images each contain one API variant, with portable
amd64-v1/arm64 tags retained. No new database migration or JSON API change.
See [AMD64 builds](docs/amd64-levels.md) and the
[performance report](docs/performance-2.5.0.md).

forwarding, durable scheduling, personal reactions/notification settings and
WebRTC calls with screen sharing. Deploy migration 000031 before the matching
frontend. Desktop notifications require an open client; restrictive NAT needs TURN.

экрана, восстановление после краткого сбоя heartbeat, сохранение ключей

# Voxhold 2.3.0

Накопительный минорный релиз от 28 октября 2026 года. Изменения относительно
**v2.2.0**; backend и frontend выпускаются с общим номером.

## Вложения и ресурсы сервера

- Файлы, скриншоты из буфера обмена, перетаскивание и короткие видео доступны
  в каналах, обсуждениях и личных/групповых беседах. Лимит входного файла — 64 МиБ.
- Картинки сжимаются на сервере до 2560 пикселей по стороне; сохраняется прозрачность.
  Есть просмотр внутри приложения, увеличение, проигрывание MP4/WebM и скачивание.
- Загрузка показывает прогресс. Повтор сохраняет ID файла и ключ сообщения,
  включая потерянный ответ после успешного сохранения на сервере.
- В настройках сервера — общая диаграмма и распределение места между изображениями,
  файлами/видео и записями звонков. Резерв диска — 15%; квоты применяются на backend.
- Очистка по категории и периоду сначала рассчитывает количество и объём, затем
  удаляет только подтверждённый набор. Более поздние загрузки сохраняются.
- Владелец очищает также записи других участников. В сообщениях остаётся заглушка
  удалённого вложения. Забытые загрузки и файлы удалённых каналов очищаются фоном.

## Личные беседы и входящие

- Из профиля участника можно написать лично или создать беседу до 16 участников.
  Есть история, непрочитанное, выход из беседы, приватность и блокировка.
- По умолчанию писать могут участники общего сообщества. Блокировки проверяются
  в обоих направлениях при создании и каждой отправке, в том числе в группах.
- «Входящие» объединяют упоминания, ответы и непрочитанные ответы отслеживаемых
  обсуждений. Переход открывает нужное сообщение и его ветку.
- Обновления объединяются в пакеты; ошибка настроек не скрывает успешно
  загруженные уведомления. Чтение личных сообщений учитывает положение прокрутки.

## Роли и обсуждения

- Владелец создаёт роли с именем и цветом, назначает их участникам и задаёт
  чтение, публикацию, голос, запуск стримов и управление сообщениями/закрепами.
- Несколько ролей складываются. Права защищают HTTP, историю/поиск, файлы,
  WebSocket и активные медиасессии. Незатронутые звонки остаются подключёнными.
- Предпросмотр роли показывает доступ к каналам без смены аккаунта. Ролям можно
  открывать закрытые каналы; бейджи видны в сообщениях и профилях.
- Обычные текстовые сообщения получили обсуждение справа, подписку и собственное
  непрочитанное. Цитирование в основной канал сохраняет прежнее поведение.
- Просмотр не считается явной отпиской; явная отписка сохраняется после новых
  ответов. Чтение канала не теряет непрочитанные ответы отдельного обсуждения.

## Обновление и проверки

Сохраните согласованную копию БД и каталога данных. Сначала backend **2.3.0** и
миграции **000027–000030**, затем frontend **2.3.0**. Откат этих миграций удаляет
новые роли, беседы, подписки и метаданные вложений: для восстановления нужен бэкап.
Публикация релиза не обновляет рабочий сервер автоматически.

```sh
./update.sh --backend-version 2.3.0 --frontend-version 2.3.0
```

Регрессии проверяют атомарную привязку файлов и квоты, область доступа, сжатие,
идемпотентность, блокировки, явные отписки, отзыв активных медиаправ и миграции.
Обязательные gates: backend tests/vet/Linux race/leaks; frontend typecheck/lint/
unit/build и браузерные UI/performance suites. Дополнительно выполнен сценарий
новых функций на отдельном backend в Docker.

[API и миграции](https://github.com/LoonEman1/voxhold-backend/blob/v2.3.0/docs/community-2.3.md)

# Voxhold 2.2.0

Минорный релиз от 28 октября 2026 года. Ниже перечислены изменения **относительно
v2.1.0**, включая исправления, слитые в `dev` до подготовки этого выпуска.
Backend и frontend имеют общий номер версии.

## Новостные каналы

- Добавлен тип канала `news`. Владелец и администраторы могут публиковать;
  дополнительных авторов назначают индивидуально в настройках канала.
- Обычным читателям доступны публикации и реакции. Право публикации проверяет
  backend при отправке, пересылке в ленту и редактировании постов.
- Приватность использует существующие ACL. Назначение автором не открывает
  закрытый канал без отдельного права доступа.
- Под постом можно включить отдельное обсуждение. Ответы на комментарии остаются
  внутри исходного обсуждения; есть пагинация, реакции, редактирование и модерация.
- Отключение комментариев запрещает новые ответы, сохраняя историю обсуждения.
  Удаление публикации удаляет её комментарии. Повторы отправки не создают дубликатов.
- Счётчик комментариев входит в revision поста и журнал синхронизации; HTTP и
  WebSocket передают `thread_root_id` и `comment_count`.
- Во frontend появились выбор новостного типа, настройки авторов и комментариев,
  лента без поля публикации для читателей и панель обсуждения рядом с постом.
- Группа «Новостные каналы» находится выше текстовых и голосовых. Если на выбранном
  сервере нет доступных новостных каналов, группа скрыта. Закрытые недоступные
  каналы не раскрываются даже присутствием группы.

## Уведомления и прочтение

- Подходящие новые уведомления сохраняются для подключённых и офлайн-аккаунтов.
  Счётчик восстанавливается после перезагрузки и повторного подключения.
- `GET /api/v1/servers/{serverID}/notification-counts` возвращает счётчики только
  доступных текущему пользователю каналов. Значения также включены в список каналов.
- Чтение с любого устройства уменьшает счётчик. Удаление сообщения, канала или
  членства очищает связанные уведомления; свои сообщения, отключённые уведомления
  и повторы отправки не увеличивают число.
- Для новостных каналов по умолчанию уведомляются все новые посты, для текстовых —
  упоминания. Комментарии новостной ленты уведомляют упомянутого пользователя или
  получателя ответа, не всех читателей канала.
- Бейдж показывает число до `99+`; полное значение доступно в подсказке и
  доступном имени. Точка остаётся для непрочитанной активности без отдельного уведомления.
- Frontend пакетно обновляет счётчики при уведомлении, прочтении, восстановлении
  синхронизации и возвращении фокуса. Запоздалые ответы не восстанавливают старый бейдж.
- Исправлено зависание отметки прочтения после повторного запуска React effects
  в StrictMode: отменённый animation frame больше не блокирует последующие проверки.

## Ответы и история сообщений

- Нажатие на цитату немедленно переводит к сообщению, уже находящемуся в кеше.
- При загрузке далёкого оригинала текущая история остаётся видимой.
- Повторные нажатия используют один запрос контекста; устаревший HTTP-ответ
  не заменяет более позднюю выбранную цель.
- Повторный выбор той же цитаты снова центрирует её сообщение.
- Комментарии используют обновления истории, цитат и реакций; удалённый оригинал
  отражается в цитате и состоянии ответа.

## Трансляции, звук и записи

- Звуковая кнопка раскрывает регулятор при наведении и фокусе с клавиатуры:
  на карточке в комнате, в мини-плеере, развёрнутом и полноэкранном режиме.
- Автор регулирует реальный уровень исходящего аудио демонстрации. Зритель
  независимо регулирует локальное воспроизведение.
- Выключение звука и нулевое положение ползунка сохраняют предыдущий ненулевой
  уровень, который восстанавливается при включении.
- Повторный `stream.leave` для уже закрытой сессии подтверждается `stream.left`
  с исходным request ID. Это позволяет продолжить автоматическое восстановление зрителя.
- Клиент также принимает ответ старого backend о уже закрытой сессии, сопоставляет
  подтверждения leave с запросом и игнорирует ошибки от предыдущей попытки воспроизведения.
- Список записей возвращает настроенную владельцем `quota_bytes`, лимит файла и
  срок хранения обычным авторизованным участникам. Управление хранилищем и сведения
  об общем использовании остаются у владельца.
- Окно записей показывает фактическую квоту инстанса и обновляет данные при открытии.
- В голосовой панели добавлены подписи «Микрофон», «Звук», «Экран» и «Выйти».
  Замок приватного канала увеличен и размещён рядом с названием.

## Обновление и откат deployment

- Updater сохраняет ссылки фактически запущенных контейнеров **до** изменения
  желаемых версий в `.env`. Immutable digest получается через inspect image ID,
  а не отсутствующее поле RepoDigests у контейнера.
- `.last-good.env` записывается до изменения работающего стека; rollback сохраняет
  исходную точку восстановления и предпочитает неизменяемые digest.
- Добавлен `--frontend-version` для согласованного выбора двух образов;
  выбор версий несовместим с одновременным `--rollback`.
- Проверяется здоровье обоих официальных компонентов. Если backend или frontend
  остаётся unhealthy, обновление завершается с ошибкой. Для стороннего frontend
  без healthcheck сохранена проверка состояния running.
- Неудачный pull не меняет работающий стек. Регрессии покрывают прежний дефект
  manifest, парный выбор версий, ошибки health/pull и повторный rollback.

## Документация, установка и разработка

- Обновлены английские и русские README backend, frontend и deploy; добавлены

- В deploy указано парное обновление backend/frontend 2.2.0 и миграции 25–26.

## Обновление и совместимость

Сохраните проверенную резервную копию базы. Сначала установите backend **2.2.0**
и примените миграции **000025–000026**, затем frontend **2.2.0**.

```sh
./update.sh --backend-version 2.2.0 --frontend-version 2.2.0
```

Команда выполняется из репозитория deploy. Миграции применяются перед запуском
backend. Старые сообщения не воспроизводятся как новые уведомления.
Откат миграции 25 удаляет комментарии и назначения авторов, сохраняя публикации
как текстовые сообщения; восстановление обсуждений требует соответствующего бэкапа.

Публикация образов и исходников не запускает обновление рабочего сервера.

## English overview

Compared with 2.1.0, this release adds private news channels with assigned
publishers and optional post discussions, persistent unread-notification badges,
clearer channel locks and labelled call controls. It also includes all reviewed
dev fixes for cached reply navigation, context-request races, stream audio gain
and mute restoration, viewer recovery, idempotent leave acknowledgements and
effective recording quota metadata. README files now cross-link all repositories
and include fixture-based UI examples; local Compose and CI artifact paths are updated.
Upgrade backend and migrations 25–26 before frontend. Federation remains design-only.


## Voxhold 2.1.0

Совместимый минорный релиз по результатам аудита 27 октября 2026.

- Исправлены отложенные переговоры WebRTC и восстановление ICE при изменении дорожек.
- Начальное подключение ограничено 20 секундами на SDP answer и 30 секундами на connect;
  ожидающий publisher track зритель не отключается по этому таймеру.
- Исправлены ротация авторизации, запоздалые 401 и координация вкладок браузера.
- Каталог участников полностью восстанавливается после reconnect и не затирается
  старым HTTP-ответом. Участники с доступом к каналу обновляются без кнопки «Обновить».
- Общая валидация SDR/HDR renditions, исправление trusted IP в deploy/Caddy,
  корректная семантика явно пустого server ICE.
- Изоляция WebSocket fan-out от дорогого cleanup, пакетный ACL и фоновая очистка expired sessions.
- Отдельная диагностика только на loopback, воспроизводимые Pion/UDP load smoke tests.
- Пустая голосовая комната оформлена компактной карточкой; запись, архив и чат
  получили отдельные понятные иконки и подписи.

Backend first, then frontend. Новых миграций нет (последняя — 24).
Для trusted IP нужно также обновить Caddyfile из Voxhold-deploy.
Старые CLIENT/SERVER ICE-наборы целиком наследуют legacy только когда namespace
полностью отсутствует; явно заданный пустой namespace отключает ICE для своей стороны.
Диагностика выключена по умолчанию; DIAGNOSTICS_LISTEN_ADDR допускает только loopback IP.

Validation: Linux tests with race + goroutine leak checks, go vet; frontend
TypeScript/ESLint/unit/production build and browser UI suites; real Caddy integration;
54 direct synthetic media scenarios. See docs/audit-2.1.ru.md for measurements,
exact scope and remaining WAN/browser/architecture work. Production was not deployed.

## 2.0.0

Первый общий релиз фронтенда и бэкенда с одинаковым номером версии.

- Ответы на сообщения с переходом к оригиналу и обновлением цитаты после
  редактирования или удаления.
- Пересылка в доступные каналы с сохранением автора. Повтор после ошибки сети
  использует тот же ключ запроса и не создаёт дубликат.
- Реакции: быстрый выбор, раскрываемая палитра, поиск, категории, недавние эмодзи,
  счётчики и список участников при наведении.
- Исправлено первое открытие записей: рабочая область и звонок остаются на месте
  во время загрузки окна.
- Список участников с доступом к каналу обновляется по событиям без ручного
  обновления.
- Единый Gitflow: feature PR → dev → релизный PR в main. В обоих репозиториях
  защищены main и dev; образы, теги и GitHub Releases выпускаются автоматически.
- Go CI проверяет гонки и утечки горутин через профиль runtime Go 1.27.

Правила X.Y.Z: X — глобальные изменения, Y — новые совместимые функции,
Z — исправления текущей минорной версии. Подробности в docs/release-workflow.md.

Для обновления сначала установите backend 2.0.0 и миграцию 24, затем frontend
2.0.0. Перед миграцией сохраните проверенную резервную копию базы данных.
