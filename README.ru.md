# Backend Voxhold

Self-hosted backend для Voxhold: HTTP API, события реального времени, голосовые
комнаты и демонстрация экрана. Сервер написан на Go, хранит данные приложения в
SQLite и распространяется как мультиплатформенный контейнерный образ.

**Связанные репозитории:** [Frontend](https://github.com/LoonEman1/voxhold-frontend)
· [Развёртывание](https://github.com/LoonEman1/voxhold-deploy).

## Новое в 2.3

Вложения, личные и групповые беседы, входящие, пользовательские роли и
обсуждения в текстовых каналах. Квоты и очистка доступны владельцу.
[API, миграции и обновление](docs/community-2.3.md).

## Возможности

Личное избранное с заметками, пересылка между каналами и беседами, отложенная
отправка, опросы, события, журнал администрации и звонки в ЛС описаны в
[документации новых функций](docs/community-features.md). Требуется миграция **000031**.


- регистрация по приглашениям и токен-сессии;
- участники серверов, роли, баны и удаление аккаунта;
- текстовые, голосовые и новостные каналы;
- приватность каналов, назначение авторов новостей и включаемые комментарии;
- сообщения, ответы, пересылка, реакции, редактирование, удаление, поиск и закрепы;
- состояние чтения и сохраняемые счётчики непрочитанных уведомлений;
- записи каналов, превью, квоты хранения и аватары;
- авторизованные события реального времени через WebSocket;
- динамический CORS allowlist для внешних браузерных клиентов;
- голосовые WebRTC-комнаты с ретрансляцией через сервер;
- серверная или peer-to-peer демонстрация экрана;
- настраиваемая защита от злоупотреблений, блокировка входа и лимиты соединений;
- миграции SQLite и идемпотентная первоначальная настройка инстанса;
- корректное завершение работы, healthcheck и запуск контейнера не от root.

## Технологии

- Go 1.27.3;
- маршрутизация на стандартном `net/http`;
- SQLite через `modernc.org/sqlite` без runtime-зависимости от CGO;
- `coder/websocket` для транспорта реального времени;
- Pion WebRTC для голоса и потоковой передачи.

Контейнер содержит три команды:

- `voxhold` — API, WebSocket и WebRTC-сервер;
- `voxhold-bootstrap` — создаёт первоначальный инстанс и владельца;
- `migrate` — применяет миграции схемы SQLite.

## Быстрый локальный запуск

Требуются Docker Engine и Docker Compose v2.

```bash
cp .env.example .env
docker compose up --build
```

При первом запуске сначала выполняются миграции, затем bootstrap и API. Если
`BOOTSTRAP_PASSWORD` оставлен пустым, сохраните сгенерированный пароль владельца:

```bash
docker compose logs bootstrap
```

Локальный API доступен по адресу `http://localhost:8080`. Healthcheck
`GET /healthz` возвращает `204 No Content`. Стандартные медиапорты:
`50000/udp` для голоса и `50001/udp` для демонстрации экрана.

Остановка локального стека без удаления SQLite volume:

```bash
docker compose down
```

Compose-файл этого репозитория предназначен для локального или backend-only
запуска. Для публичного сервера с HTTPS, Caddy, резервными копиями,
автообновлением и заменяемым сайтом используйте
[`LoonEman1/voxhold-deploy`](https://github.com/LoonEman1/voxhold-deploy).

## Образы, версии и обновление

Backend и [frontend](https://github.com/LoonEman1/voxhold-frontend) выпускаются
с общим номером **2.3.0**. Для этой версии нужны миграции **000027–000030**:
роли, подписки обсуждений, личные беседы и вложения. Сначала обновляется backend
с миграциями, затем frontend. Перед обновлением сохраните проверенную резервную копию.
Порядок и семантика миграций: [общение и управление 2.3](docs/community-2.3.md).

```bash
docker pull ghcr.io/looneman1/voxhold-backend:2.3.0
```

Точный тег `2.3.0` обозначает релиз; `2.3` и `latest` перемещаются при следующих
публикациях. OCI digest является неизменяемой ссылкой. CI публикует образы для
`linux/amd64` и `linux/arm64` с SBOM и provenance.

Изменения проходят feature PR в `dev`, затем релизный PR `dev` → `main`.
Новый `VERSION` в успешном main CI запускает публикацию образов, аннотированного
тега `v2.3.0` и GitHub Release. Отдельно создавать тег не требуется; существующий
релиз не перезаписывается. Подробности: [общий workflow](docs/release-workflow.md)
и [описание релизов](RELEASE_NOTES.md).

Для установленного production-стека используйте команды из
[Voxhold deploy](https://github.com/LoonEman1/voxhold-deploy/blob/main/README.ru.md):

```bash
./update.sh --backend-version 2.3.0 --frontend-version 2.3.0
```

Команда запускается в каталоге deploy. Его Compose выполняет миграции до старта
нового backend; updater сохраняет страховочный бэкап и проверяет healthcheck.

## Обзор API

Публичный префикс API — `/api/v1`.

- `/api/v1/instance` — информация об инстансе и версия протокола;
- `/api/v1/instance/cors-origins` — управление разрешёнными origin владельцем;
- `/api/v1/auth/*` — регистрация, вход, обновление и завершение сессии;
- `/api/v1/me/*` — текущий профиль, серверы и входящие приглашения;
- `/api/v1/servers/*` — участники, роли, баны, каналы и приглашения;
- `/api/v1/servers/*/channels/*/messages` — история и изменение сообщений;
- `/api/v1/servers/*/notification-counts` — непрочитанные уведомления текущего пользователя;
- `/api/v1/servers/*/channels/*/news` — управление авторами и комментариями;
- `/api/v1/servers/*/messages/search` — полнотекстовый поиск сообщений;
- `/api/v1/ws` — события, голос и signaling демонстрации экрана.

`GET /api/v1/servers/{serverID}/channels` возвращает `last_message_id` для
каждого канала, поэтому клиент может сравнить его с состоянием прочтения без
загрузки истории сообщений каждого канала. Для канала без сообщений значение
равно `0`. В ответ также входят `unread_count`, персональное право
`can_publish` и `comments_enabled`. Подробности — в [описании новостных каналов](docs/news-channels.md).

Защищённые HTTP-endpoint используют `Authorization: Bearer <token>`. Регистрация
возможна только по приглашению. После подключения WebSocket-клиент проходит
аутентификацию и получает актуальные состояния участия, чтения, присутствия,
голоса и стримов.

OpenAPI-документ пока не публикуется. Обработчики маршрутов в
`internal/*/http` являются источником истины для полей запросов и ответов.

### Динамический CORS allowlist

Владелец инстанса может заменить весь список без перезапуска backend. Изменения
сразу применяются к HTTP-запросам и новым WebSocket-соединениям и сохраняются в
SQLite:

```bash
curl -X PUT https://api.example.com/api/v1/instance/cors-origins \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  --data '{"origins":["https://client.example.com","http://localhost:5173"]}'
```

Текущий список возвращает `GET /api/v1/instance/cors-origins`. Запрос `PUT`
полностью заменяет его; `{"origins":[]}` очищает список. Каждый элемент должен
быть точным `http`- или `https`-origin (схема, хост и необязательный порт), без
пути, query-параметров и wildcard. Клиенты с тем же хостом и встроенный Wails-
клиент разрешены автоматически и в сохранённом списке не отображаются.

## Конфигурация

Скопируйте [`.env.example`](.env.example) и проверьте каждое значение перед
развёртыванием. Основные группы:

- `DATABASE_*`, `MIGRATIONS_PATH`, `RESET_DATABASE` — жизненный цикл SQLite;
- `INSTANCE_NAME`, `BOOTSTRAP_*` — однократная инициализация инстанса;
- `HTTP_*`, `TRUST_PROXY_HEADERS` — HTTP listener и доверенный proxy;
- `AUTH_*`, `INVITE_*`, `LOGIN_*`, `WS_*` — защита от злоупотреблений;
- `WEBRTC_*` — публичный адрес, UDP-порты, лимиты и необязательный STUN/TURN.

На публичном сервере `WEBRTC_PUBLIC_IP` должен содержать доступный публичный
адрес сервера, а настроенные UDP-порты должны быть открыты в firewall хоста и
провайдера. Включайте `TRUST_PROXY_HEADERS`, только если API доступен
исключительно через доверенный reverse proxy, перезаписывающий forwarding
headers.

## Разработка

```bash
go mod download
go test ./...
go vet ./...
```

Локальная сборка бинарных файлов:

```bash
go build ./cmd/api
go build ./cmd/bootstrap
```

PR CI выполняет тесты, vet, race и проверку утечек горутин, а также собирает
`linux/amd64` без публикации. Успешный main CI публикует обе платформы, только
если `VERSION` обозначает новый релиз; остальные push не перезаписывают
существующие версии. Подробности — в [release workflow](docs/release-workflow.md).

## Безопасность

Не публикуйте SQLite-файлы, `.env`, Docker socket или HTTP-порт backend напрямую
в Интернет. Завершайте TLS на доверенном reverse proxy и открывайте только TCP
80/443 и настроенные UDP-порты WebRTC.

Не сообщайте об уязвимостях через публичный issue. Следуйте инструкции в
[SECURITY.md](SECURITY.md).
